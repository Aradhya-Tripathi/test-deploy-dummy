How it works

From git push to traffic in five steps

  1. 1

    Push

    A commit lands on the tracked branch. GitHub tells Central.

    git push origin main
  2. 2

    Queue

    Central records a Deploy Request. A newer push cancels the older build.

    Deploy Request
  3. 3

    Build

    The VM's agent picks it up, fetches only that commit, and builds the Dockerfile.

    buildah build --layers
  4. 4

    Release

    The image starts in the idle slot and must pass the health check and stay up.

    GET /health
  5. 5

    Switch

    nginx points at the new slot, then the old one stops. A failure changes nothing.

    upstream.conf

The image

A five-stage Dockerfile

Only the last stage ships. The others build assets, resolve dependencies, and refuse to produce an image when a test fails.

  1. assetsnode:22-alpine

    npm ci with a cache mount, esbuild bundles and minifies the CSS and JS.

  2. depspython:3.12-slim

    uv resolves Flask and gunicorn into a self-contained virtualenv.

  3. testpytest gate

    Runs the suite against the built assets. A failing test fails the build, so nothing is released.

  4. metabusybox

    Reads the detached .git/HEAD and stamps the commit and build time you see above.

  5. runtimeslim · non-root

    Venv, templates, and assets only. Runs gunicorn as uid 10001 on $PORT.
